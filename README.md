# Advanced Layer Cake

Пресет для OpenWrt 25.12 и SQM. Windows может помечать исходящие пакеты отдельных приложений через Policy-based QoS. Роутер запоминает класс соединения и применяет его к ответам, даже если сервер не выставляет DSCP.

В примере политика Windows задает DSCP 46 для Overwatch и DSCP 8 для qBittorrent и Steam. Правила по этим меткам стоят выше правил по портам, поэтому приложения можно различать, даже если все используют 443. CAKE направляет их в Voice и Bulk соответственно. Если ни одно правило не совпало, соединение получает DSCP 0 и очередь Best Effort. Очередь Bulk может использовать свободную полосу. [Как задать метку DSCP для приложения в Windows](https://learn.microsoft.com/windows-server/networking/technologies/qos/qos-policy-top)

## Установка

На OpenWrt 25.12 установите зависимости:

```sh
apk add sqm-scripts luci-app-sqm tc-full kmod-sched-ctinfo
```

Нужна команда `nft`, которая уже есть на стандартной прошивке с `firewall4`. Перед обновлением сохраните свой файл `/etc/config/advanced_layer_cake`. Если на роутере запускался старый пресет, сначала отключите его в SQM и перезагрузите роутер один раз, чтобы удалить его таблицу и очереди.

```sh
cp Advanced_Layer_Cake.qos Advanced_Layer_Cake.qos.help /usr/lib/sqm/
cp -n advanced_layer_cake /etc/config/
```

1. В **Network → Firewall** выключите software и hardware flow offloading. Ускоренные соединения могут пропускать правила маркировки на отдаче.
2. В **Network → SQM QoS** выберите WAN, задайте скорости чуть ниже измеренной пропускной способности и выберите `Advanced_Layer_Cake.qos`. Значение `0` отключает ограничение скорости в соответствующем направлении.
3. В **Queue Discipline → Advanced Configuration** выберите **Ignore DSCP (ingress) → Allow**, чтобы CAKE учитывал классы на скачивании. **Squash DSCP (ingress)** можно оставить включенным, если метки не нужны после очереди.

При наличии правил пресет по умолчанию использует `diffserv4`. Настройки `eqdisc_opts` и `iqdisc_opts` SQM применяются последними.

## Правила

В [шаблоне `advanced_layer_cake`](advanced_layer_cake) перечислены все поля для каждого класса. Заполните нужные поля и оставьте остальные как `''`. При запуске пресет не добавляет в nftables проверки для пустых полей. Первое совпадение побеждает. Все заданные условия секции должны совпасть.

| Поле | Значения |
| --- | --- |
| `match_dscp` | Входная метка DSCP, число от 0 до 63 |
| `match_src_ip`, `match_dst_ip` | IP, CIDR, диапазон или список через запятую. Один тип адресов в секции: IPv4 или IPv6 |
| `match_protocol` | `TCP`, `UDP`, `ICMP`, `ICMPv6` или список |
| `match_port` | Порт назначения, диапазон или список. Без протокола применяется к TCP и UDP |
| `set_dscp` | Обязательная метка для обоих направлений, число от 0 до 63 |

В смешанном правиле поле порта действует только на TCP и UDP. Правило без условий действует на все соединения, поэтому может стоять только последним. Пустой файл включает обычный CAKE без правил маркировки. Ошибка в файле останавливает запуск с сообщением в журнале.

Чтобы доверять меткам конкретного компьютера, добавьте `match_src_ip` к правилам DSCP. Например:

```text
config class 'Games'
    option match_src_ip '192.168.1.50'
    option match_dscp '46'
    option set_dscp '46'
```

Правила проверяются на первом пакете соединения, который роутер видит на отдаче. Условия смотрят на адреса до исходящего NAT. Пакеты, пришедшие до первой классификации, идут через CAKE с исходным DSCP. Уже открытые соединения сохраняют класс при перезапуске SQM. Для проверки измененного правила откройте новое соединение.

Пресет использует биты `0xfd000000` в метке соединения и стандартную зону conntrack (0). При использовании других классификаторов и правил маршрутизации убедитесь, что они не занимают эти биты и не перезаписывают всю метку соединения. Для нескольких WAN конфиг общий, а класс выбирается один раз на соединение.

## Проверка

- `logread | grep -i 'Advanced Layer Cake'` показывает ошибки загрузки и настройки.
- `nft list tables` показывает таблицы `alc_*`. В цепочке `classify` счетчики отражают совпадения при выборе класса.
- `tc -s qdisc show dev <WAN>` и `tc -s qdisc show dev <IFB>` показывают фактические очереди и статистику по классам. Имя IFB видно в `tc filter show dev <WAN> ingress`.
- Если правило Windows не совпадает, проверьте DSCP входящих с компьютера пакетов на LAN роутера. Для проверки обратного направления смотрите счетчики CAKE на IFB.
